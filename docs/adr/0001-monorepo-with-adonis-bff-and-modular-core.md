# Separate the Adonis BFF from the modular application core

This boilerplate uses a PNPM workspaces monorepo with the Adonis application in `apps/web` and reusable UI in `packages/design-system`. Inside the web application, `app` is the single root for both delivery and application code, organized by business capability rather than by technical layer. `app/<capability>` holds that capability's controllers, routes, middleware, models, repositories, transformers, types, and validators, while `app/core` holds the foundations shared across capabilities, such as the exception handler, middleware, model mixins, and the base repository. Each capability is reached through its own import alias, `#<capability>/*` or `#core/*`, which makes the capability the unit of ownership: delivery adapters depend on actions, queries, repositories, and domain objects, and those building blocks never depend back on delivery. This keeps controllers thin without preventing business modules from using framework facilities when they add value.
